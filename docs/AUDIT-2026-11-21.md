## 3. 确定缺陷 / 潜在竞态 / 性能假设

- **确定缺陷（已修）**：`/state` 可覆盖任意 U-Boot 环境变量；OTA 仅同源 SHA256、无发布者
  认证；父进程可能在子进程完成 `setpgid` 前发布 PID；下载大小只做进度分母。
- **潜在竞态（已加固，待真机压力）**：UI 崩溃/模拟器 exec 失败/合盖同时发生时，PID 复用
  与进程组信号；代码已用 comm + PGID 双重校验并 fail-closed。
- **性能假设（未测量）**：PGO 命中率、DrawCall/脏矩形收益、CPU governor 对帧时间的影响。
  路线图明确：PC/qemu 数据不能替代 RK3568 真机结论。

## 4. 最高风险

1. **OTA 私钥丢失**：私钥在构建机 `~/.gameos-ota-signing/ed25519.pem`，不在仓库/镜像；
   丢失后已发布设备无法安装新签名更新。必须离线备份；泄露则需轮换公钥并先发一版旧钥
   签名的过渡固件。
2. **旧 release 未签名**：启用 fail-closed 后，设备会拒绝旧版本 OTA；这是预期行为，但
   升级路径需从“已签名的新 release”开始。
3. **刷机后 p4 被清零的根因未定位**：上一次写卡出现 p4 全零，已从校验过的备份恢复；
   在修好会失效缓存的后置检查前，不再刷写数据分区。
4. **CI 缺失**：GitHub OAuth App 无 `workflow` scope，无法推送 workflow；本地测试可跑，
   但 PR 级自动回归仍缺位。
5. **真机测试缺口**：启动/双屏/音频/Wi-Fi/蓝牙/睡眠/OTA 断电注入均未在本轮执行。

## 5. 建议顺序

1. 先在真机启动本轮镜像，收集 `G:\system\ui-perf.log`（PR-06 基线）与 OTA 签名失败/成功用例。
2. 用独立构建目录做 melonDS baseline vs PGO A/B（PR-06），再决定是否保留 PGO。
3. 只测量 CPU/GPU 策略（PR-07）与 DRM 双屏提交（PR-08），有数据后再改默认值。
4. CI workflow 需用户提供带 `workflow` scope 的凭据；在此之前用本地 `tests/shell/test-*.sh` 回归。
5. PR-19 的 NES/SNES/MD 采用路线图 §26 的“成熟核心优先”方案，已交付上游核心接入；
   用户提出的自研核心目标仍未完成，应作为独立里程碑，不与 P0/P1 修复混批。
   三个平台的硬件验收（帧时间/温度/功耗/存档）在 `docs/PLATFORMS.md` 中全部标为 `NOT RUN`。
